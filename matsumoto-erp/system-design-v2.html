Context

MTI is the Jakarta arm of Matsumoto Trading Co., Ltd. (Tokyo). It imports specialty cosmetic and pharmaceutical ingredients from Japan, clears them through customs, holds them at a forwarder warehouse, and distributes to Indonesian manufacturers. The business previously ran on one shared Excel workbook; this build replaces that workbook with a database-backed application.

Version 1.0 was the proposed design. This document (v2.0) describes what was actually built and delivered: the chosen stack, the implemented document chain, the data model, and how it is deployed with Docker.

Key design decisions

PO & QREach Purchase Order renders a PDF with a QR code encoding the PO number + a token. The QR is the fast path into the receive screen.
Receive to stockScanning the QR or typing the PO / supplier DN loads the PO lines; posting a Goods Receipt creates one inventory lot per line and raises stock in the same transaction.
Three-way matchA supplier invoice attaches to a Goods Receipt, so PO ↔ GR ↔ Supplier Invoice are reconciled before payment.
Stock & FEFOStock is held by lot with mfg/expiry dates. Deliveries deduct first-expiry-first-out and can't exceed what's on hand.
Customer invoice linkageInvoices are raised from a Delivery Order; the PO number and Surat Jalan number flow onto the invoice automatically, with PPN 11%.
Masters as linksFinish Goods link to a Customer and to a Raw Material (stock source); Raw Materials link to a Supplier, with HS code & LARTAS for customs.

Architecture & deployment

Three containers via Docker Compose. The web container (Nginx) serves the built React app and proxies /api to the backend; the API talks to PostgreSQL over the internal network.

On first boot the API waits for the DB, runs prisma db push, and seeds MTI sample data. One command: docker compose up --build.

Environments. Config via .env (ports, DB credentials, SEED_ON_START). The Docker build runs prisma generate, which downloads the Prisma engine — the build host needs outbound internet. Development uses seeded synthetic data; production data is loaded after go-live.
